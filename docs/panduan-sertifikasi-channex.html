01. Arsitektur & Peta Navigasi 5-Pilar Channel Manager
Arsitektur Terpadu

Channex adalah penyedia infrastruktur Channel Manager global yang menghubungkan My Tara CRS dengan 68+ Online Travel Agent (Booking.com, Agoda, Expedia, Traveloka, Airbnb, Trip.com, dll.). Agar My Tara mendapatkan status Official Certified PMS Partner, My Tara harus lulus audit teknis terhadap protokol sinkronisasi 2 arah.

⚜️
Prinsip Inti yang Dinilai oleh Tim Audit Channex:
1. Kepatuhan 2-Call Full Sync: Sinkronisasi massal 500 hari dikirim dalam 2 request API terpisah (Call 1: Allotment Kamar, Call 2: Tarif & Restriksi).
2. Delta Update Batching: Setiap perubahan tanggal/harga jamak wajib digabung (batch) ke dalam 1 request API, dilarang melakukan looping per tanggal.
3. Mandatory Booking ACK Loop: Setiap reservasi webhook yang diterima wajib dikonfirmasi balik via POST /booking_revisions/:id/ack dalam batas SLA 30 menit.
4. Task ID Tracking: Channex memproses data secara antrean latar belakang (*async*). Respon sukses mengembalikan Task ID yang wajib dicatat di formulir.

TEST 1 Full Data Update (Full Sync 500 Hari)
2 API Calls Wajib

Tujuan: Mensimulasikan kondisi hotel saat pertama kali *Go Live* atau pemulihan paska *downtime*. Mengirimkan 500 hari ketersediaan dan tarif sekaligus.

⚠️
Perhatian Khusus Channex: Channex menolak data yang seragam/flat (misal semua kamar availability 1 dan harga $100 sepanjang tahun). Data harus bervariasi menyerupai operasional hotel riil.
Panggilan API Cakupan Feed Target Payload Batas Waktu
Call 1 Availability (Allotment) 500 Hari ke depan untuk Twin Room & Double Room 1 Request
Call 2 Rates & Restrictions 500 Hari tarif & 7 restriksi untuk 4 kombinasi Rate Plan 1 Request
Cara Eksekusi di Menu Baru: Buka tab=sandbox Testing Sandbox atau tab=golive > Klik tombol "Force Push ARI to Channels (500 Hari)". Sistem akan mengeksekusi 2 panggilan API bertahap dan mencatat 2 Task ID pada tab=logs Transmission Logs.

TEST 12 — 14 Standar Operasional Teknis & Kepatuhan Arsitektur
Compliance

Test 12: Kepatuhan Batas Request (Rate Limits)

Pertanyaan Channex: "Can you stay in rate limits? Do you have a queue or limiter to not spam our API endpoints?"
Jawaban Resmi: YES. My Tara CRS mengimplementasikan antrean terpusat (*job queue*) dengan pembatasan maksimal 10 request per detik, exponential backoff retry otomatis saat menerima status 429 / 5xx, dan penggabungan payload dinamis.

Test 13: Logika Sinkronisasi Efisien (Larangan Polling Timer)

Pertanyaan Channex: "Do you agree to only send updated changes to Channex? (No full sync on a 5-min timer)"
Jawaban Resmi: YES, AGREE. My Tara menerapkan 100% *Delta-based updates*. Sinkronisasi ke Channex hanya dipicu saat terjadi modifikasi tarif atau pemesanan kamar. Full Sync hanya diizinkan manual via tab=golive atau maksimal 1x setiap 24 jam pada jam sepi (*off-peak*).

Test 14: Matriks Kepatuhan Fitur Tambahan (Technical Specifications)

Pertanyaan Channex di FormulirJawaban Resmi yang Harus Dipilih
Do you support both Min Stay Through and Arrival? Both (Min Stay Through and Min Stay Arrival are supported).
Do you support restrictions (Stop Sell, CTA, CTD)? Yes, all 8 restrictions (Stop Sell, CTA, CTD, Max Stay) are supported.
Do you support multiple room types & rate plans? Yes, fully supported with dynamic derived & non-derived rate plans.
Do you need credit card details with bookings? Optional (Tokenized / Masked, managed per hotel policy via tab=payments).
